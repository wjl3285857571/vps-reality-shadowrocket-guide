# 01｜完整部署流程

本文从一台可通过 SSH 管理的新 VPS 开始，部署原生 Xray-core REALITY 节点。所有尖括号内容都是占位符，不能原样照抄。

## 1. 部署前需要准备什么

准备以下信息，但不要把它们写进 GitHub：

```text
<VPS_IP>               VPS 公网地址
<SSH_USER>             SSH 管理用户
<SSH_PORT>             SSH 端口，通常为 22
<REALITY_TARGET>       目标站点和端口，例如 target.example:443
<REALITY_SERVER_NAME>  与目标证书匹配的 SNI
```

REALITY 的 `target` 和 `serverNames` 不是随便填写的。它们需要满足当前 Xray 官方文档的约束，且目标站点应从 VPS 所在网络稳定可达。官方文档还提示：未经认证的流量可能被转发到 `target`，选错目标可能带来滥用和转发风险。

## 2. 定义成功标准

开始前先明确最终要观察到的结果：

1. Xray 配置语法正确；
2. Xray 服务处于 `active`；
3. Xray 监听 TCP 443；
4. 防火墙保留 SSH 并放行节点端口；
5. 外部客户端能够完成 REALITY 握手；
6. 真实网页请求确实从 VPS 出口发出；
7. Shadowrocket 能长期保持连接；
8. DNS、WebRTC、IPv4 和 IPv6 检测符合预期。

## 3. 先做服务器基线检查

SSH 登录后执行只读检查：

```bash
cat /etc/os-release
uname -m
systemctl --version | head -n 1
ss -lntp
df -h /
free -h
```

重点确认：

- 系统是仍受支持的 Ubuntu/Debian；
- CPU 架构受到 Xray 支持；
- 443 没有被其他服务占用；
- 磁盘和内存没有明显不足；
- SSH 当前连接稳定。

如果 443 已被 Nginx、Caddy、3X-UI 或旧 Xray 占用，不要强行覆盖。先查清服务归属：

```bash
sudo ss -lntp | grep ':443'
sudo systemctl --type=service --state=running
```

## 4. 创建服务器备份

任何写操作前创建带时间戳的备份目录：

```bash
STAMP="$(date -u +%Y%m%dT%H%M%SZ)"
BACKUP_DIR="/root/reality-backup-${STAMP}"
sudo mkdir -p "$BACKUP_DIR"
sudo cp -a /usr/local/etc/xray "$BACKUP_DIR/" 2>/dev/null || true
sudo cp -a /etc/systemd/system/xray.service "$BACKUP_DIR/" 2>/dev/null || true
sudo cp -a /etc/ufw "$BACKUP_DIR/" 2>/dev/null || true
sudo cp -a /etc/fail2ban "$BACKUP_DIR/" 2>/dev/null || true
echo "$BACKUP_DIR"
```

记录输出的备份目录路径，但不要把备份内容上传到 GitHub。

## 5. 安装原生 Xray-core

推荐使用 XTLS 官方安装仓库。先下载到临时文件，再执行，便于观察和审计：

```bash
sudo apt-get update
sudo apt-get install -y curl ca-certificates openssl

curl -fL --retry 3 \
  https://github.com/XTLS/Xray-install/raw/main/install-release.sh \
  -o /tmp/install-xray.sh

less /tmp/install-xray.sh
sudo bash /tmp/install-xray.sh install
rm -f /tmp/install-xray.sh
```

安装后检查：

```bash
/usr/local/bin/xray version
systemctl status xray --no-pager
```

安装成功只代表程序存在，不代表节点配置已经可用。

## 6. 生成节点身份材料

在 VPS 本地生成，不要在聊天或文档中粘贴输出：

```bash
umask 077
UUID="$(/usr/local/bin/xray uuid)"
/usr/local/bin/xray x25519 > /root/.reality-keypair.tmp
SHORT_ID="$(openssl rand -hex 8)"
```

不同 Xray 版本的 `x25519` 输出标签可能不同。当前版本可能使用 `PrivateKey:` 与 `Password (PublicKey):`。不要仅根据旧教程硬编码解析方式，必须检查非敏感的字段名称，并确认两个值都非空。

安全边界：

- 服务端私钥只能保存在服务端配置；
- 客户端所需的公开材料也不应发布到公共仓库，因为它们与地址、UUID、Short ID 组合后就是完整节点凭据；
- 临时密钥文件完成解析后应删除；
- 客户端信息文件权限应为 `600`。

## 7. 写入 REALITY 配置

仓库提供的脚本会自动生成配置：

```bash
sudo REALITY_TARGET='<REALITY_TARGET>' \
  REALITY_SERVER_NAME='<REALITY_SERVER_NAME>' \
  LISTEN_PORT='443' \
  bash scripts/install-reality.sh
```

如果你手动配置，核心结构应包含：

```json
{
  "inbounds": [
    {
      "listen": "0.0.0.0",
      "port": 443,
      "protocol": "vless",
      "settings": {
        "clients": [
          {
            "id": "<UUID>",
            "flow": "xtls-rprx-vision"
          }
        ],
        "decryption": "none"
      },
      "streamSettings": {
        "network": "raw",
        "security": "reality",
        "realitySettings": {
          "show": false,
          "target": "<REALITY_TARGET>",
          "xver": 0,
          "serverNames": ["<REALITY_SERVER_NAME>"],
          "privateKey": "<REALITY_PRIVATE_KEY>",
          "shortIds": ["<SHORT_ID>"]
        }
      }
    }
  ],
  "outbounds": [
    {"protocol": "freedom", "tag": "direct"},
    {"protocol": "blackhole", "tag": "blocked"}
  ]
}
```

文档里的占位符不能用于真实部署。

## 8. 配置校验与启动

不要直接重启。先校验：

```bash
sudo /usr/local/bin/xray run -test \
  -config /usr/local/etc/xray/config.json
```

通过后再执行：

```bash
sudo systemctl enable xray
sudo systemctl restart xray
sudo systemctl is-active xray
sudo ss -lntp | grep ':443'
sudo journalctl -u xray -n 50 --no-pager
```

如果配置校验失败：

1. 不要重启服务；
2. 保留当前 SSH 会话；
3. 检查 JSON 语法和当前版本支持的字段名；
4. 恢复备份配置；
5. 再次运行 `run -test`。

## 9. 防火墙与基础防护

安装基础工具：

```bash
sudo apt-get install -y ufw fail2ban unattended-upgrades
```

必须先放行实际 SSH 端口，再启用 UFW：

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow <SSH_PORT>/tcp comment 'SSH'
sudo ufw allow 443/tcp comment 'Xray Reality'
sudo ufw logging low
sudo ufw --force enable
sudo ufw status verbose
```

配置 Fail2ban：

```ini
[sshd]
enabled = true
backend = systemd
port = <SSH_PORT>
mode = normal
maxretry = 5
findtime = 10m
bantime = 24h
```

保存到 `/etc/fail2ban/jail.d/sshd-local.conf` 后验证：

```bash
sudo fail2ban-client -t
sudo systemctl enable --now fail2ban
sudo systemctl restart fail2ban
sudo fail2ban-client status sshd
```

不要因为启用了 Fail2ban 就使用简单密码。

## 10. SSH 加固的边界

SSH 密钥登录能保护服务器管理入口，但不会直接改善 DNS、WebRTC 或浏览器 IP 泄露。

如果暂时保留密码登录，至少设置：

```text
MaxAuthTries 3
LoginGraceTime 30
MaxStartups 10:30:60
PermitEmptyPasswords no
ClientAliveInterval 300
ClientAliveCountMax 2
```

修改后必须先执行：

```bash
sudo sshd -t
```

只有在以下条件全部满足时，才考虑关闭密码登录：

1. 私钥由用户本人安全保管；
2. 新终端窗口已用密钥成功登录；
3. 已保留当前 SSH 会话；
4. VPS 提供商有控制台或救援模式；
5. 已验证 `sshd -t`；
6. 已准备回滚命令。

## 11. 客户端参数处理

客户端至少需要：

```text
地址、端口、UUID、Flow、Security、SNI、Fingerprint、REALITY 公钥/Password、Short ID、Network
```

这些字段组合起来就是可使用的节点凭据。正确做法：

- 在 VPS 上保存为 `/root/reality-client.env`；
- 权限设为 `600`；
- 通过自己控制的安全通道下载；
- 在本地保存到不受 Git 管理的私有目录；
- 导入 Shadowrocket 后删除临时传输副本；
- 不把 URI、二维码或截图上传到 GitHub。

## 12. Shadowrocket 导入与基础验收

导入后先不要调整 DNS。先确认节点本身：

1. 选中刚导入的节点；
2. 全局路由保持原来的“配置”；
3. 保持 Shadowrocket 开启；
4. 运行内置连通性测试；
5. 打开普通网页；
6. 检查 IPv4/IPv6 出口；
7. 再进行 DNS 优化。

如果节点不通，先检查服务、监听、日志和客户端字段是否一致，不要通过同时修改 DNS、IPv6 和路由来“碰运气”。

## 13. 完成标准

最终记录以下不敏感结果即可：

```text
Xray 配置：通过/失败
Xray 服务：active/inactive
TCP 监听：正常/异常
外部连接：成功/失败
客户端实测：成功/失败
IPv4/IPv6 地区：符合/不符合预期
DNS 运营商：符合/不符合预期
WebRTC：正常/泄露
回滚路径：已记录/未记录
```

不要记录真实 IP、UUID、密钥或节点 URI。
